# 모든 도메인 공통 규칙

## 폴더

- `raw/` 원본. 메모 하나가 파일 하나. 절대 고치거나 지우지 않는다.
- `raw/<id>.source.md` 링크 본문이나 영상 자막처럼 수집 스크립트가 붙인 자료. 역시 고치지 않는다.
- `wiki/` LLM이 관리하는 페이지.
- `wiki/answers/` 저장된 질문 답. 정리 작업의 근거로 쓰지 않는다.
- `wiki/index.md` 스크립트가 frontmatter에서 생성한다. 직접 고치지 않는다.
- `wiki/log.md` 작업 기록. 맨 아래에 덧붙이기만 한다.
- `wiki/_review.md` 판단이 애매한 것을 모아 사람이 나중에 본다.

## 원본 메모 frontmatter

```yaml
id: 01JB8Z...              # ULID
captured_at: 2026-10-29T08:10:00+09:00
tz: Asia/Seoul
location: { lat: 37.5, lon: 127.0, place: "종로구 사직동", address: "서울특별시 종로구 사직동 123-45" }   # 없을 수 있음. place는 앱에 보이는 이름, address는 번지까지
source: typed | share | selection | voice | chat | feed | agent
domain_hint: 스터디 | null
context: { project: notes-app, cwd: /Users/me/workspace/notes-app, branch: main }   # agent만. 메모를 쓸 때 작업하던 곳
routing: { by: hint | classifier | fallback, confidence: 0.92 }   # 서버가 라우팅할 때 붙임
```

`source: chat`은 채팅 중 내가 알려준 사실이다. 예를 들어 "그 영상 봤어". 다른 메모와 똑같이 사실로 취급한다.

## 위키 페이지 frontmatter

```yaml
type: <이 도메인의 페이지 종류 중 하나>
summary: 한 줄 요약. index.md에 그대로 들어간다
aliases: [다른 이름, 별칭]
status: active | outdated | disputed
sources: [원본 id 목록]
updated: 2026-10-29
```

## 정리 작업 순서

1. 원본과 `.source.md`를 읽는다.
2. 먼저 판정한다. 새 페이지 / 기존 페이지 수정 / 기존 내용과 충돌 / 정리할 거리 없음.
3. 새 페이지를 만들기 전에 `index.md`와 모든 페이지의 `aliases`에서 같은 대상을 찾는다. 같은 대상이면 기존 페이지를 고친다.
4. 바뀐 사실은 덧붙이지 말고 본문을 고쳐 쓴다. 옛 내용이 의미 있으면 "이전에는" 문단으로 남기고 날짜를 단다.
5. 충돌이나 확신이 없는 판단은 `_review.md`에 적고 페이지에는 `status: disputed`를 단다.
6. 원본에 없는 사실을 지어내지 않는다. 모든 주장에는 근거 원본 id를 단다.
7. 2번의 판정과 고친 페이지 목록을 구조화된 응답으로 돌려준다. `log.md`와 `index.md`는 서버가 쓰므로 건드리지 않는다.

`log.md` 한 줄의 형식은 `## [YYYY-MM-DD] <작업> | <id> | <판정> | <고친 페이지들>`이다. 판정 자리에 `실패 k/N`, `중단 k/N`, `포기 N/N`, `재시도`, `이동 → <도메인>`이 오면 작업 기록이다. 이 파일은 작업 상태의 원천이므로 사람도 줄을 지우지 않는다.

## 링크

- 페이지끼리는 `[[페이지 이름]]`으로 잇는다. 없는 페이지로 링크하지 않는다.
- 다른 도메인 페이지는 `[[도메인/wiki/페이지 이름]]`.
